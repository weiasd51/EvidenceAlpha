# 14 天学习路线（每天约 8 小时）

目标不是背代码，而是能独立解释、修改和验证系统。

## 第 1～3 天：跑通与跟踪

- 启动前后端，完成一次宁德时代研究。
- 在浏览器 Network 中观察 `POST /api/v1/analyses`。
- 从 `backend/main.py` 跟到 `services/workflow.py`，再跟到数据库模型。
- 自己画一次请求的时序图。

验收：不看文档讲清楚请求从页面到预测账本的路径。

## 第 4～6 天：数据与时点

- 阅读 `providers/demo.py` 和 `models.py`。
- 将一条证据的发布时间改到研究时点之后，确认它不会被返回。
- 增加一个新的演示股票和一条风险证据。
- 理解 `published_at`、`ingested_at` 和 `as_of` 的区别。

验收：能解释什么是未来数据泄漏，以及本项目如何避免。

## 第 7～9 天：Agent 工作流

- 阅读 Research/Bull/Bear/Critic/Judge 的职责。
- 对比 `single` 和 `debate` 的调用轨迹。
- 修改裁决权重，并为修改补测试。
- 设计一个不会让 Bull/Bear 自行引入新证据的 LLM Prompt。

验收：能回答为什么不把所有逻辑都交给一个 Agent。

## 第 10～11 天：预测与评测

- 手动结算一条预测。
- 推导 Brier Score 计算过程。
- 制造一个高置信度错误案例，观察指标变化。
- 解释准确率为什么不足以评价系统。

验收：能用具体样本解释校准和消融实验。

## 第 12～14 天：工程化与面试

- 执行测试、构建和 Docker 部署。
- 增加一个真实数据 Provider，保留演示 Provider 作为测试桩。
- 整理 Git 提交、架构图和演示视频。
- 使用 `docs/INTERVIEW_GUIDE.md` 自测，并独立讲述 10 分钟。

验收：能现场增加一个字段、修复一个测试，并解释设计取舍。
